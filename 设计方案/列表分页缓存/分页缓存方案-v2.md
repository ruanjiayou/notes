# 列表分页缓存 v2 设计方案

> 本文件是 v2 的**唯一依据**，与 v1（`分页缓存方案.md`）不兼容，v1 待本方案落地后废弃。
> 定稿时间 2026-09-24。

## 0. 已拍板的决策

| # | 决策 | 结论 |
| --- | --- | --- |
| 1 | meta 字段 | **只留 `total`**；`count` / `over` / `synced_to` 全部删除 |
| 2 | count 从哪来 | 每次读 `ZCARD(list)`，不落 meta（副本会说谎） |
| 3 | 到底判定 | `zcard(list) >= meta.total` |
| 4 | total 取值 | `model.count()`；**每次 EXTEND 都查**，不是只在取尽时查 |
| 5 | over | **不要**。取尽由 total 与 zcard 的关系表达 |
| 6 | 扩展推不动水位线 | 视为取完，**返回已有数据**（不抛错）；`count < total` 留给监控 |
| 7 | idx 摘除 | 只在「`GET meta` 返回 nil」时 `SREM`；删空**不摘** |
| 8 | idx TTL | 与 list / meta **完全相同** |
| 9 | 读路径 | **每次读续期三个 key** |
| 10 | 返回体 | `{ list, next, total }` |
| 11 | 向前扩展兜底 | **不做**（正常链路用不到，见 §7） |
| 12 | 游标 `e` | **可选**：缺省不做过期校验，带了才校验（1403） |
| 13 | 旧数据迁移 | **不做**：功能尚未上线，上线即 v2，直接按本方案写 |

## 1. 数据模型

```
keyList  = {prefix}:{combo}:list    ZSET   成员 = member，score = 毫秒
keyMeta  = {prefix}:{combo}:meta    STRING JSON { total }
keyIndex = {prefix}:idx             SET    成员 = 组合名
```

- `combo`：`all` 表示全部类型；否则 `types.slice().sort().join('_')`，如 `article_ticker`。
- `member` 恒为 `id + '_' + type`，与组合无关，同一前缀下所有组合共用一套 member 字符串。
- **硬约束**：id **等长且不含下划线**。
  等长 → ZSET 同分按 member 字节序排 == 源库按 id 排；
  不含下划线 → 全仓统一用 `member.split('_')` 反解 `[id, type]`，且 type 后缀可用于筛组合。
- `score` 是时间字段的毫秒数（`new Date(v).getTime()`）。
- `fields = [scoreField, idField, typeField]`，缺省 `['modified_time','res_id','res_type']`；
  `order = [[scoreField, dir],[idField, dir]]`，`dir` 由 `rev`（默认 true = 倒序）决定。
- MySQL 的 id 列必须二进制排序（`utf8mb4_bin`），否则 `ORDER BY id` 与 member 字节序错位。

## 2. 不变式

- **INV-1（到底）**：`next = null` ⟺「取不足 size+1 条」且「`zcard >= total`」。
- **INV-2（索引）**：`idx` 含某组合 ⟺ 该组合的 meta 存在。
  `SREM` 只允许发生在 `GET meta` 返回 nil 时；`SADD` 只在 EXTEND 里幂等做。
  这是「删空后新增还能进 list」的前提——摘掉索引 = 新增永久丢失。
- **INV-3（原子 + 同寿）**：list 与 meta 的写入在同一段 Lua 内完成；三键同 TTL、同一时刻续期。
- **INV-4（不谎报）**：扩展推不动水位线（zcard 没变）就停止并返回已有数据。
  绝不因为「查不到」就宣称到底。
- **INV-5（读只用 score 区间）**：读路径只用 `Z[REV]RANGEBYSCORE`，禁用 `ZRANK/ZREVRANK/ZRANGE`；
  唯一例外是 EXTEND 的**尾部探针**（`ZRANGE key 0 0 WITHSCORES` / 升序 `ZREVRANGE`）。
- **INV-6（total 只准偏高，不准偏低）**：publish 的 `total ±1` 只在 ZSET **真的变了**
  （`ZADD`/`ZREM` 返回 1）时才做。偏低会让 `zcard >= total` 提前成立 → **截断漏读**；
  偏高只是多扩展一次，是安全方向。

## 3. 读路径

一次读 = 一段 Lua（`LUA.READ`），**一次往返**拿到「数据 + count + total」，顺便续期三键：

```
KEYS[1]=list  KEYS[2]=meta  KEYS[3]=idx
ARGV[1]=命令名('ZREVRANGEBYSCORE'|'ZRANGEBYSCORE')
ARGV[2]=边界a ARGV[3]=边界b ARGV[4]=offset ARGV[5]=count ARGV[6]=ttlSec

redis.call('EXPIRE', KEYS[1], ARGV[6])
redis.call('EXPIRE', KEYS[2], ARGV[6])
redis.call('EXPIRE', KEYS[3], ARGV[6])
local items = redis.call(ARGV[1], KEYS[1], ARGV[2], ARGV[3], 'LIMIT', ARGV[4], ARGV[5], 'WITHSCORES')
local z     = redis.call('ZCARD', KEYS[1])
local raw   = redis.call('GET', KEYS[2])
local total = -1                                  -- -1 = meta 不存在（尚未建缓存）
if raw then total = cjson.decode(raw).total end
return { z, total, items }
```

-reply `total = -1` 表示「没缓存」，调用方走 EXTEND 建缓存。

### 3.1 cursor 模式

1. `READ` 取 `size+1` 条（首页全区间；有游标则闭区间 `[-inf, t]` / `[t, +inf]`）。
2. 取满 `size+1` → 交付 `size` 条 + `next` 游标，**结束**（无额外命令）。
3. 取不满且 `total < 0`（没缓存）→ EXTEND → 回 1。
4. 取不满且 `zcard >= total` → 到底，`next = null`，结束。
5. 取不满且 `zcard < total` → EXTEND → 回 1；**zcard 没变就停**（INV-4），按现有数据返回。

同分 band：窗口从 offset 0 起读，按 **member 字典序**过滤已交付前缀（倒序留 `member <= m`），
**不用 offset 跳过**（前缀被删后计数会右移 → 漏读）；窗口不够时 2 倍放大，上限 `MAX_SCORE_BAND`。

### 3.2 page 模式

```
depth = (page-1)*size + size + 1
if (total < 0) EXTEND()                            -- 先建缓存
while (count < depth && count < total) EXTEND()    -- zcard 没变就 break
READ(offset, size+1)
```

`count >= total` 时即使没到 depth 也停——源库就这么多了，不足一页是真实结果。

### 3.3 游标

`base64url({ t, m?, o?, e? })`

- `t = items[size].score`（探察项），下一页 **闭区间**从 t 读起。
- `m` / `o` 仅当 `probe.score === anchor.score`（页边界落在同分 band 内）时携带，
  `o = (cursor.o||0) + k`，仅当 `cursor.t === anchor.score` 才累加。
- `e` = 签发时刻 + ttl（毫秒），**可选**：缺省不做过期校验，带了才校验（过期 → 1403）。
  类签发时照常带 `e`（缓存 TTL 4h，跨 TTL 的游标没有意义）；`e` 可选是给外部构造 /
  长期保存的游标留的口子。
- 解析在类外（`decodeCursor(raw, now)`，同文件导出），类只接受 `{t,m,o}`。

## 4. 扩展（EXTEND）

```
KEYS[1]=list KEYS[2]=meta KEYS[3]=idx
ARGV[1]=members(JSON [[member,score],...]) ARGV[2]=total ARGV[3]=ttlSec ARGV[4]=combo

for each member: ZADD KEYS[1] score member
meta = { total = tonumber(ARGV[2]) }               -- 由 JS 的 model.count() 得到，每次都刷新
SET KEYS[2] cjson.encode(meta)
SADD KEYS[3] ARGV[4]                               -- 幂等登记索引
EXPIRE × 3
return { ZCARD(KEYS[1]), tonumber(ARGV[2]) }
```

JS 侧顺序：

1. 尾部探针 `ZRANGE key 0 0 WITHSCORES`（升序用 `ZREVRANGE`）→ 空则无续点、从头取；
2. `model.findAll({ where + keyset 续点, order, limit: step })`
   —— keyset 拼在 `where` 里：`[Op.or]: [{score:{[Op.lt]:at}}, {score:at, id:{[Op.lte]:id}}]`（升序用 gt/gte），
   `at` 要用 `new Date(ms)` 转回 Date（时间列比毫秒数会按字符串比）；
3. `model.count({ where })` —— **每次扩展都查**，total 因此永不漂移；
4. `EVAL` 写回。

`step` 必须 **≥ 2**：续点是闭区间，每批会重取边界那条，`step=1` 水位线净推进 0。

## 5. 写入侧（publish）

```
publish(key, value, score, action, ttl) -> { value, changed, stale }

1. combos = SMEMBERS {prefix}:idx
2. 逐个 combo：
   a. 类型筛选：member 后缀即 type；'all' 通吃，否则 combo 名须含该 type，不含则跳过
      （既不算 changed，也不算 stale，也不动 TTL）
   b. EVAL(LUA.CHANGE, keys=[list, meta, idx], argv=[add|del, member, score, ttl])
      local raw = GET meta; if not raw then return -1 end
      changed = ZADD / ZREM
      if changed == 1 then total = total ± 1（下限 0）end   -- 只在真变了时（INV-6）
      SET meta; EXPIRE × 3
      return changed
   c. -1 → SREM idx combo（唯一允许的摘除点）+ 记入 stale；1 → 记入 changed；0 → 都不记
```

`action > 0` 为新增。同一 member 重复写幂等（由 ZADD/ZREM 返回值决定是否计数）。

## 6. 常量与错误码

| 项 | 值 | 说明 |
| --- | --- | --- |
| `size` | 15 | 页大小 |
| `step` | 200 | 每次扩展向源库取多少条，必须 ≥ 2 |
| `ttl` | 4h | 三键同值；读 / 扩展 / 写入都续期 |
| `MAX_SCORE_BAND` | 800 | band 窗口放大上限 |
| `MAX_PAGE_DEPTH` | 10000 | page 模式深度上限 |

| 码 | 含义 |
| --- | --- |
| 1401 | page 翻页深度超限，请改用游标 |
| 1402 | 游标非法 |
| 1403 | 游标已过期（仅当游标带了 `e`），重置到首页 |
| 1500 | 源库 / Redis 异常（**不用于「缓存够不着」**，那种按 INV-4 降级返回） |

## 7. 失效矩阵

| 丢什么 | 现象 | 自愈 |
| --- | --- | --- |
| list 没了（淘汰 / 误删），meta 在 | `zcard=0 < total` | EXTEND 探不到尾部 → 从头全量取 → 补回 ✓（v1 的 over 在这里是死局） |
| meta 没了，list 在 | `total = -1` | 按冷启动：从尾部续 → count() 定 total → 顺手 SADD idx ✓ |
| idx 里组合没了，meta 在 | publish 遍历不到 | 读路径不受影响；新增在此期间进不了 list（已知取舍，下次 EXTEND 重新登记） |
| total 偏高（脏行 / 漏送的 del） | 末页多一次 EXTEND | 每次 EXTEND 都 count()，下一轮即校正 |
| total 偏低（重复 del） | 可能提前判到底 | 用 INV-6 堵死（只在真变了才 ±1） |
| DB 多了行但没 publish | `count < total` 且推不动 | 按 INV-4 返回部分；每次末页多一次 EXTEND，TTL / 下次 EXTEND 收敛 |

最后一行是**唯一**会触发「向后推不动」的场景（批量导入、别的服务直写库、publish 抛错没重试）。
正常链路下不会出现：meta 在 ⟺ 组合在 idx ⟹ publish 能更新 total ⟹ 扩展取尽时 count() 定准
⟹ `zcard >= total`。因此**不做**向前扩展兜底。

## 8. 与 v1 的差异（对照）

功能尚未上线，**没有存量数据要迁移**：上线即 v2，v1 代码与 v1 文档直接作废，不需要兼容
旧 meta 的读取分支。

| v1 | v2 |
| --- | --- |
| meta `{count, over}` | meta `{total}` |
| `over === true` 判到底 | `zcard >= total` 判到底 |
| `synced_to` 存续点 | 续点 = ZSET 尾部探针 |
| 删空顺手 `SREM idx` | 删空**不摘** idx（v1 那个 bug：删空后新增永久丢失） |
| EXTEND 不查 count | EXTEND 每次 `model.count()` |
| 读不续期 | 读也续期（热列表不再自然过期） |
| 返回 `{list, next}` | 返回 `{list, next, total}` |
| 游标 `e` 必填（缺 / 非法即 1403） | `e` 可选，缺省不校验过期 |
