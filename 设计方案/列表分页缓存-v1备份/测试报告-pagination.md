## 一、结论

1. **分页正确性成立**：41 / 463 / 471 / 1291 条四个规模下，「逐页拼接」与「ZSET 全量顺序」完全一致，无重复、无漏读（A3/A5/B4/C3/C5/E3/F2/F3 反复验证）。
2. **同分不是边界特例，是常态**：score 是秒级（MySQL DATETIME），一次导入几百条常常落在同一个 score；实测出现 346 / 54 / 38 条的大 band。因此**游标模式的 band 逻辑在真实流量里必然被触发**，库内游标单测不可省。
3. **页模式（接口当前唯一模式）在 band > 800 时依然完整**：注入 850 条同分，band 内与 band 之后逐页拼接全部正确（C5）。`MAX_SCORE_BAND=800` 只约束游标模式。
4. **写入侧是异步生效的**（约 30ms），见风险 R1。
5. 无 P0 缺陷；发现 3 处需要知晓的行为（R1/R2/R3）。

## 二、方法与范围

**四个接口**（登录只带 `fengshows-client`，其余都要再加 `token`）：

| 用途 | 请求 |
|---|---|
| 登录 | `POST /oauth/login`（phone 13872184014 / code 86 / password 123456aa / ticket 写死） |
| 列表 | `GET /history/list/<page>?res_type=article_ticker`（page 0 起，页大小 15） |
| 新增 | `POST /history/create/_bulk`，body 直接是数组 |
| 删除 | `POST /history/del/_bulk`，body `{ids:[...]}` |

**Redis 校验**：只读/只写 `user:v6:history:<uid>:*`（`:list` / `:meta` / `:idx`）。所有写操作经过前缀守卫，越界即抛错；所有删除只针对本脚本创建的 `res_id`（`delOwn`），不会删到账号真实历史。

**不在范围内**：游标模式的 band 过滤 / `o` 累加 / `MAX_SCORE_BAND` 放大收敛 —— 接口只暴露页模式（`data` 是数组，不含游标），这些只能由库内单测（`test/*.test.js`）覆盖。

## 五、发现与风险

### R1（中）新增接口返回时缓存还没更新 —— 异步 publish，实测约 30ms

`POST /history/create/_bulk` 返回 `status:0` 后立即读 `/history/list/0`，**看不到刚新增的记录**；轮询实测约 32ms 后才进缓存。
影响：客户端「新增成功后立刻刷新列表」会短暂看不到自己的新记录。
建议（择一）：服务侧 `await publish(...)` 后再返回；或列表侧对「刚写入的 id」做乐观插入；或客户端稍后重试。

### R2（中）反向索引 idx 丢失期间的新增，在缓存过期前一直不可见

idx 被 maxmemory 淘汰 / 被 flush / 被手工删除后：`publish` 取不到候选组合 → 静默跳过 → 增量丢失；此后即使 `_extend` 重新登记 idx，**那条记录仍在缓存之外**（因为它比 `synced_to` 新，而 `_extend` 只向更旧方向续取）。
正常 TTL 一致时不会发生；属于可接受的取舍，但建议：`publish` 发现 idx 为空（或返回 stale）时，主动触发一次该组合的缓存重建，或让列表接口在「source 有、cache 无」时兜底回源。
（E3 中一致性恢复是靠清缓存整体重建达成的。）

### R3（中）只丢 list、meta 还在 → 列表静默返回空，4 小时内不自愈

`meta.complete === true` 时读路径不再触发扩展，因此 list 被单独删除（或部分成员丢失）会导致列表返回空/偏少，直到 meta 一起过期。
建议：读路径对「`meta.count > 0` 但 `ZCARD == 0`（或 ZCARD 明显小于 count）」做一次一致性兜底（重建或校正 count）。

### R4（低）接口参数未校验

`page` 传 `abc` / `-1` / `1.5` 都按第 0 页正常返回（应为 1400）；`res_type` 缺失按 all 处理。建议中间件补校验，`ListPagination` 本身按约定不做校验。

### R5（低）C6 无法在接口层覆盖

页模式没有游标入参，同分 band 内的删除语义（游标模式的核心取舍）只能靠库内单测。若希望 E2E 也能覆盖，可给列表接口加一个 `cursor` 入参。
